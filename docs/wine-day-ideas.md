## Current customer action

`marketing-design.js` owns the single team-enquiry flow. Selecting an authored card retains its ID/title/region/default vehicle in memory. Pickup/date/party are reviewed with a changeable requested vehicle and optional winery/return notes. Edit and Clear day idea preserve the visitor's other draft fields. Both party and requested-vehicle choices use the existing scoped Compact picker.

Final action is **Send quote request**, with name and reply email collected in the existing cream review panel. `quote-request.js` owns contact validation and one immutable, memory-only submission attempt. `POST https://koast-chat.euburaga.workers.dev/quote-requests` carries requestId(UUIDv4), createdAt(epoch milliseconds), name, email, pickup, date(empty allowed), party(1-6 or7+), region, requested vehicle, optional tourId/tourTitle, notes and public page path without query/hash. Server-side `workers/koast-chat/quote-requests.mjs` bounds/validates the request and sends a plain-text transactional enquiry through Resend to the fixed reserve@koastride.com inbox, with the customer's email as Reply-To. No client-controlled sender/recipient, model call, customer confirmation email, account/contact creation, booking, pricing, payment or SMS action.

The endpoint requires the separate sending-only `QUOTE_EMAIL_KEY`, verified Koast-domain `QUOTE_EMAIL_FROM` in the exact form `Koast Website <address@koastride.com>` (verified subdomains supported), and both native quote rate-limit bindings. Missing configuration/trusted edge IP or limiter errors fail closed. Allowed origins are exactly the two production Koast hosts. JSON streams are bounded to8192bytes; header/control injection, unsupported vehicle/party/date/path, oversized notes and a filled honeypot are rejected. Native limits are3/minute per hashed edge-IP and20/minute per shared location key; they are approximate per-location inbox guards, not authentication, comprehensive bot protection or a worldwide spending cap. No new database or assistant access is introduced; existing Resend is reused, and this explicitly submitted public form is separate from tool-less Kopilot.

Success requires a provider acceptance receipt, then returns only `{ok:true,reference}`. It means accepted for delivery, not confirmed inbox receipt or a reservation. The browser locks the exact attempt during pending/unknown outcomes; double clicks do not send twice and retries reuse the exact body and provider idempotency key `website-quote/<requestId>`. Attempts older than23h are blocked before Resend's documented24h key retention ends. Definite pre-send400validation permits correction; unavailable/timeout/rate-limit/unknown outcomes retain details and reference for manual retry/help. Closing/reopening the dialog retains the attempt while the page remains open. Reload/navigation loses the memory-only draft; no background retry, durable queue or new lead database is claimed. Form fields never enter analytics or browser persistence. Existing manual email is an optional help fallback, with the reference, rather than the primary submission action. Delivered/bounced status is checked through the email provider; a production release needs a labelled internal acceptance message and independent inbox/delivery evidence.
